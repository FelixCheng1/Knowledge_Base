## 关键问题

### P1：下一批必须处理

1. **问题理解被静默禁用（新增）。** `app/finance/service.py:240` 使用 `json.loads`，文件没有导入 json，异常被宽泛捕获并返回默认理解结果。合法模型输出也无法启用摘要、澄清和指代改写。应补齐导入、结构校验和可观察错误；对象不明时不能无条件降级为全库检索。增加合法 JSON、非法 JSON、上下文切换回归。

2. **版本隔离不完整（旧问题未闭环）。** `service.py:97` 后的新逻辑把旧向量清理移到激活之后，这是改进；但 `search` 没有 `active_version_id` 过滤，相邻补全也没限定版本。未激活/部分写入的新版本、清理失败留下的旧版本都可能被检索。导入时将整份文档改为 processing，又会使按实体查询的旧活动版本暂时不可见。必须独立记录候选版本处理状态，并让所有检索只读取活动版本。

3. **相邻补全会丢切片和混版本（新增）。** `service.py:309` 按 `(document_id, block_index)` 去重，一个大表拆成多个 chunk 时会互相覆盖；邻块查询仅过滤文档与 block。改用稳定 chunk ID，保留同一 block 的所有分片，严格过滤版本，再按文内顺序补全。

4. **引用与答案不能一一核对（旧问题仍在）。** `service.py:337` 固定返回前 4 条引用，却把全部证据编号交给模型，答案可能使用 [5]～[12]。`api.py:143` 文件接口只返回当前活动版本；前端忽略引用版本和页码。需要证据编号到稳定引用 ID 的映射、实际引用校验、按版本获取原文与页码定位。历史答案必须打开当时版本。

5. **新会话答案存在被历史加载覆盖的竞态（新增流式 UI 暴露）。** `frontend/src/main.tsx:43` 路由切换触发历史读取，随后 `setMessages(result.items)` 可能覆盖第 55 行插入的临时助手消息。之后 delta/final 只按临时 ID 更新，目标消失便无法展示答案。将历史、在途查询和流式消息统一按 query_id 合并，并测试首问与切换会话。

6. **断线后不能持续恢复（未完成）。** `api.py:260` 断线清理队列；处理中的查询重连可能找不到队列。前端第 66 行仅读一次状态，若仍在 processing 就停止等待，没有继续轮询。需要按 query_id 恢复最终结果、页面刷新后找回在途任务、明确终态与超时。不要把连接断开直接等同于任务失败。

7. **元数据存在实际错误（旧问题）。** 回放中“私募基金投资者教育知识问答”和“消费者金融素养问卷调查报告”被分为 wealth_management；统计公报中的 `808879` 等统计数字进入 codes；招商银行报告的 `2026年3月31日` 被写为 publish_date。基金资料也使用第一个日期，混淆编制与送出日期。应按正文标签、机构角色与上下文识别，日期无依据留空，人工修正同步实体和检索数据。

8. **首次部署的 Milvus 初始化顺序错误（新增）。** `service.py:431` 在第 443 行创建索引之前加载新集合。无索引的新集合可能加载失败，已有索引环境会掩盖问题。调整为建 schema → 建索引 → 加载，使用全新临时集合完成回归。

### P2：在问答验收前补齐

- **全文摘要尚不是全文。** `_summarize` 只接收 top-k 检索和邻块结果，没有按指定文档/版本读取所有章节；`target_document_title` 未用于检索限定，`time_scope` 也没有用于过滤。修复理解模块后仍不能直接宣称全文摘要已完成。
- **章节、表格和 FAQ 结构不足。** MinerU 已提供 `text_level`，但 `_load_blocks` 丢弃该字段并统一设空 section。切片仅按长度和标点处理，未保持 FAQ 问答对、跨表表头与单位。实测最长切片 6002 字符，900 字符配置没有保证硬上限；应按内容结构及模型输入预算处理，避免硬截表格。
- **证据充分性缺少机制。** 当前只在证据列表为空时拒答；无法保证低相关、对象不明、报告期冲突时不作答。精确代码通过正则模糊查询，名称未匹配可能放宽到全库。应区分精确代码/标准名/别名与候选匹配，建立对象、时间、条件覆盖检查。
- **幂等与并发不可靠。** 任意版本 checksum 命中即报告 active，包括曾失败或停用版本；重试入口除 processing 外均放行，可能重跑有效版本；会话锁是先 count 再 insert，无法原子阻止并发。文档导入任务没有启动恢复，空切片也可能激活。
- **人工修正不能闭环。** patch 只更新文档字段，不同步实体与向量字段，重新解析又覆盖 metadata；应区分自动抽取和人工覆盖，明确重处理语义。
- **文件与来源契约不足。** 原文件名直接参与本地路径，应限制为安全文件名并校验落盘路径；DOC 转换文件没有持久化到版本关联，转换页码不能伪装成原 DOC 页码。结构化产物和图片也未完整登记到对象存储。
- **健康检查可能无法表达依赖故障。** Depends(get_service) 构造 Mongo repository 时即建索引，Mongo 不可用会先抛错，进不到 health 的异常处理。拆分无依赖存活检查与依赖就绪检查。
- **OpenAPI 基础正确，契约仍不完整。** POST /queries 实际返回 409，schema 仅有 202/422；DocumentPatch 类型是自由字符串；SSE 只有媒体类型没有载荷模型；文件下载响应描述和前端类型同步需补齐。建议以 OpenAPI 生成 TS 类型并纳入差异检查。
- **前端尚未完整联调。** 缺少元数据编辑、版本上传、任务进度轮询、失败重试、筛选和会话删除；会话导航不会在创建后刷新；未使用 PDF.js。当前是页面基础，不能算 T12 验收通过。
- **技术约定待收敛。** 金融主流程由 service 直接编排，未接入原规划中的 LangGraph。后续可将已验证节点接入图，但不要仅为结构迁移延后正确性修复。
